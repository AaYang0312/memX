## 3. Gold set 与数据集门禁候选（DS）

> 设计规格 §19.4 要求 Task 0 冻结"gold set 的来源、时间切分、去重与 tenant/domain 分层、每层最小样本数/标注一致性"。以下是供审批的候选定义；数据集实体本身由 Task 8/11/14 的 fixture 工作产出（§13），在此之前本文档不声称存在任何数据集。

- **DS-1（候选）数据集版本策略。** gold set 使用语义化版本 `goldset-vMAJOR.MINOR.PATCH` 并附带 SHA-256 内容 manifest：内容/切分/判级变化递增 MAJOR；仅增补标注递增 MINOR；纯元数据修复递增 PATCH。数值门禁只绑定 MAJOR 版本：MAJOR 变更即触发 §10.2 变更控制重新审批（设计规格 §19.4"真实负载变化后按变更控制重新批准"同口径）。每次评测报告必须记录：数据集版本 + manifest 哈希 + 评测器构建/配置哈希 + 种子；缺任一即运行无效（§9）。
- **DS-2（候选）来源与合规。** 仅本地合成数据（G3）：由带种子的生成器产出，生成器种子与参数写入 manifest；不使用任何真实用户/租户数据；G12 批准前不引入生产派生 queries；不虚构外部数据集或既有标注。
- **DS-3（候选）分层与样本量下限。** 分层维度 = 合成租户档（≥ 3 档：低/中/高活跃画像）× 合成 domain（≥ 4 个，分类法在冻结前固定入 manifest）× 时间窗口（DS-6）。每 (租户档 × domain × 时间窗口) 单元 ≥ 30 条已判 queries，每 (租户档 × domain) 跨窗口合计 ≥ 100 条，总计 ≥ 2,000 条。算术：3 × 4 × 3 = 36 单元，36 × 30 = 1,080 ≤ 2,000；W3 为 20% 时至少 400 条 ≥ 12 × 30 = 360 条。宏平均同时报告每个时间窗口与每层结果，不得用总量掩盖小层缺口。
- **DS-4（候选）去重与泄漏防护。** ① 规范化文本哈希精确去重；② 近重复检测（字符 shingle Jaccard 相似度 ≥ 0.8 即剔除，或仅允许保留在同一分层单元并标记）；③ 时间切分两侧禁止出现同一合成会话/主体的 queries（防跨切分泄漏）；④ 成对任务集（§6）与 gold set 的检索目标内容不得互相泄露答案（冻结评审时人工核查清单）；⑤ G12 后任何生产派生内容进入数据集都必须以新 MAJOR 版本 + 重新审批为前提。
- **DS-5（候选）标注一致性。** relevance 采用分级判定（0 = 不相关，1 = 部分/间接相关，2 = 直接回答所需）；≥ 10% queries（≥ 200 条）由 ≥ 2 名标注者独立判定；一致性以 Cohen's κ ≥ 0.70 为下限；分歧由第三名仲裁者终审；标注指南版本化并入 manifest。κ < 0.70 → 数据集不合格 → 相关门禁 FAIL CLOSED（§9）。
- **DS-6（候选）时间切分。** 合成数据按三个生成窗口 W1:W2:W3 = 50%:30%:20% 产出；W3（≥ 400 条）为时间 holdout，**永不**用于检索配置/融合权重的任何调参；门禁报告按窗口分列指标；若 W3 相对 W1 的指标相对退化 > 10 个百分点，触发发布前强制 owner 复审（这是流程触发器，不是自动 FAIL）。

## 4. 检索质量门禁候选（Q）

> 对应设计规格 §19.4 第 14 项与实施计划 §17.6（Task 11 验收）。对照基线是 **lexical BM25 baseline**（§4.4）；无记忆 baseline 不参与 retrieval 评测（实施计划 §17.6）。

### 4.1 指标定义（单位均为 [0,1] 比例；统计窗口 = 冻结数据集上的单次确定性运行）

- **precision@5**：每 query 计 |top5 中相关项| ÷ 5（分级 ≥ 1 记为相关）；先对 query 平均，再对分层单元宏平均，报告单元值与宏平均值。
- **recall@10**：每 query 计 |top10 中相关项| ÷ |该 query 判级全集中相关项总数|；无相关项的 query 从 recall 分母集合剔除并报告剔除数。
- **nDCG@10**：标准分级折损累计增益，gain = 2^grade − 1，折扣 = log2(rank+1)，IDCG 取该 query 全部判级项的理想排序。
- 确定性规则：相同分数按 `memory_ref` 字典序 tie-break；检索参数、融合权重、topK 截断、随机种子全部记录入运行 manifest（可复现性是门禁前提，§9）。

### 4.2 绝对阈值候选（对混合检索系统测量；宏平均口径）

| 候选 | 指标 | 绝对下限 | 相对 BM25 下限（点估计） | CI 条件 |
|---|---|---|---|---|
| Q-1 | precision@5 | ≥ 0.60 | ≥ +5% | Q-4 |
| Q-2 | recall@10 | ≥ 0.70 | ≥ +15% | Q-4 |
| Q-3 | nDCG@10 | ≥ 0.65 | ≥ +10% | Q-4 |

相对改善定义：`rel = (metric_hybrid − metric_bm25) ÷ metric_bm25`（同数据集、同 query 集、宏平均）；任一 BM25 对应指标为 0 时相对值无定义，须经 owner 审批数据集/口径后重跑，不能直接视为通过；通过条件 = 绝对下限满足 **且** 相对下限满足 **且** Q-4 的 CI 条件满足。三者缺一即该指标 FAIL。算术示例（防误读）：若 BM25 recall@10 = 0.55，则相对 +15% 要求混合 ≥ 0.6325，而绝对下限 0.70 更严、取 0.70；若 BM25 nDCG@10 = 0.50，则 +10% 要求 ≥ 0.55，绝对下限 0.65 更严、取 0.65。

### 4.3 置信区间方法候选（Q-4）

- 对每 query 计算配对差 `d_q = m_hybrid(q) − m_bm25(q)`；报告分层宏平均差与整体宏平均差。
- 95% CI：按分层单元内对 query 有放回重采样的分层 bootstrap 百分位法，B = 10,000；**双测 95% CI 不含 0** 方可通过。
- 未达预定样本下限（DS-3）或 CI 含 0 → **证据不足 → FAIL**（设计规格 §19.4"未达到预定样本数或置信区间要求视为证据不足"；实施计划 §6.4"证据不足不能算通过"）。
- bootstrap 固定种子并记录；CI 算法版本入运行 manifest，算法变更属 §10.2 变更控制。

### 4.4 BM25 baseline 的定义（候选）

- 实现：ES BM25（analyzer 按 G-A 当前默认：未批准前仅 standard analyzer，ADR 0002 §17 G-A）、无语义候选、无融合加分的词法-only 检索路径；同 topK 截断、同 canonical revalidation 过滤（保证对比只反映召回/排序差异，不反映过滤差异）。
- baseline 配置哈希必须入运行 manifest；baseline 缺失或不可复现 → 全部 Q 门禁 FAIL CLOSED（§9）。
- baseline 测量值（Task 9/11 首次产出）是**测量记录，不是阈值**（ADR 0002 §15 同口径）；本文档不预设 baseline 数值。
- 注意校准边界：绝对阈值与数据集难度相关。数据集首次冻结后（Task 8/11 fixture 产出时）若测量显示任一绝对下限在合成集上平凡饱和或不可达，须走 §10.2 变更控制修订并重新审批；不得以"实测已超/未达"为由绕过批准。

### 4.5 检索侧零容忍（重申，非候选）

跨租户命中 = 0、未确认 proposal / 敏感内容 / 高敏内容进入候选与 MemoryPack = 0（Z1/Z2；实施计划 §17.6）。这些是自动化测试断言，不是数值候选，不参与 Q 的统计通过逻辑。

## 5. 错误记忆率门禁候选（E）

> 对应设计规格 §19.1"错误记忆率"指标与 §19.4"错误记忆率的分母/人工标注方法与上限"。

- **E-1（候选）分母与上限。** 分母 = **非空 MemoryPack**（至少含 1 条记忆项的包）；分子 = 人工判定含 ≥ 1 条错误记忆项的包。错误分类体系：错误值 / 过期或已撤销仍出现 / 主体错误归属（含跨主体）/ 注入或不可信内容被采纳 / 超出授权范围。门禁：**点估计 ≤ 1.0%/pack 且 Wilson 单侧 95% 上界 ≤ 2.0%**。算术核对（n = 400）：观测 0 错误 → 上界 ≈ 0.67%（与"3/n 法则"0.75% 同量级）；观测 3 错误（0.75%）→ 上界 ≈ 1.86%，通过；观测 4 错误（1.00%）→ 上界 ≈ 2.21%，**不通过**（点估计虽 = 1.0%，CI 条件失败）。
- **E-2（候选）人工标注方法。** 样本量 ≥ max(全部非空 pack 的 10%, 400 pack)，从冻结成对运行 + 合成 shadow 窗口随机抽取（种子入 manifest）；≥ 2 名标注者独立判定 + 第三人仲裁；Cohen's κ ≥ 0.70；标注指南版本化。样本不足或 κ 不达 → FAIL CLOSED（§9）。
- **E-3（候选）per-item 伴随指标。** 同时报告每记忆项错误率（分母 = 抽样 pack 内全部记忆项）作诊断值，但**门禁只绑 per-pack 口径**（一包多错不重复计分子）。
- **范围注记：** 错误记忆率评测依赖 Task 11 的 MemoryPack 产出与 §13 夹具；其"上限"数值（E-1）即设计规格 §19.4 要求 Task 0 冻结的"错误记忆率上限"，当前为候选。安全相关错误子类（跨主体、越权、注入）同时受 Z1/Z2 零容忍断言约束，不因 E-1 通过而豁免。

## 6. 成对无记忆任务评测门禁候选（P）

> 对应设计规格 §19.4 第 15 项与实施计划 §17.6/§20.4：任务成功率与 Tool 正确率的收益必须由**成对离线评测**（或获批的在线对照组，另批）证明；shadow 不可替代（§7）。

- **P-1（候选）任务成功率差异。** 配对设计：同一任务集、同一被测模型/温度/种子配置，每任务运行两次（memory=off 与 memory=on，运行顺序随机化并记录）；成功率由确定性 checker（对工具调用序列与最终答案字段的结构化断言）判定，不经人工打分。门禁：**Δ成功率 = p_on − p_off ≥ +10 个百分点，且双测 95% CI 下界 ≥ +5 个百分点**。
- **P-2（候选）Tool 正确率差异。** 同一配对与 checker 口径，指标 = 工具选择与参数正确率。门禁：**Δ ≥ +10 个百分点，且 95% CI 下界 ≥ +5 个百分点**。
- **P-3（候选）样本量下限。** 任务集 ≥ 400 对，每合成 domain ≥ 60 对（4 × 60 = 240 ≤ 400，总下限独立约束）。功效演示（合成假设，二项正态近似 McNemar、双测 α = 0.05，非实测）：

  | 场景假设（discordant 结构） | 期望 discordant 对 | 检验功效 |
  |---|---|---|
  | p01=0.15 / p10=0.05 | 80 | ≈ 99.8% |
  | p01=0.10 / p10=0.05 | 60 | ≈ 74.5% |
  | p01=0.10 / p10=0.03 | 52 | ≈ 98.9% |
  | p01=0.08 / p10=0.04（最弱） | 48 | ≈ 64.5% |

  弱效应场景下 N=400 功效不足（N=600 ≈ 82%、N=800 ≈ 92%）；评审可在批准时提高 P-3 下限，或预先在评测计划中登记效应假设。**功效假设必须先于运行登记**，禁止运行后反推。
- **P-4（候选）CI 方法。** 配对比例差使用 Newcombe 混合 Wilson score 区间（配对差专用式）；配对计数用 McNemar 精确检验作 p 值交叉核对。CI 算法版本入运行 manifest。
- **P-5（候选）可归因设计。** 消融臂 ≥ 3：① no-memory（基线）；② memory-on 全量；③ 分源消融（仅 confirmed facts；+working memory；+episodic 检索，逐臂关闭）。报告按臂分解 Δ，用于归因"收益来自哪一层"；归因报告是发布评审输入，消融臂本身另设通过阈值需 owner 在批准时决定（当前不预设）。
- **在线对照组边界（已确认约束，非候选）：** 任何在线/小流量对照实验超出 Task 0 范围，须 Product + Security 另行批准（并受 G12 约束）；本文件不含在线实验门禁。

## 7. Shadow 边界（已确认约束）与观测指标候选（S）

**已确认能力边界（非候选，不得放宽）：** shadow 模式**只能**衡量检索候选覆盖、错误候选与性能/时延（设计规格 §19.4 第 15 项）；**不能**从 shadow 的未注入流量推断任务成功率、Tool 正确率或任何端到端收益（实施计划 §20.4；ADR 0002 §15）。任何把 shadow 结果表述为收益证明的评测报告即无效。

在上述边界内的观测指标候选（G12 前：仅合成 shadow；G12 后：真实 shadow 数据集须 Product 批准并作为独立数据来源登记）：

- **S-1（候选）候选覆盖。** 融合候选池（截断 top-50）对照该窗口内独立人工标注的 relevance 全集计算 recall@50 ≥ 0.85；7 天滚动窗口，按日聚合、按周门禁。真实 shadow 不能假定已有 gold 标签；标签/候选池不完整则仅报告覆盖诊断，门禁为证据不足，不得借离线 gold set 代替真实窗口标注。
- **S-2（候选）错误候选率。** 每窗口随机抽样 ≥ 200 条通过 canonical revalidation 的候选做人工复核，判为非相关（wrong-candidate）的比例 ≤ 10%；双人复核 ≥ 10% 样本。另：revalidation 丢弃率（stale/已删/越权命中被丢弃的比例）作为**投影健康诊断量**报告（丢弃率升高指向投影滞后，不是模型质量问题），不设通过阈值。
- **S-3（候选）时延。** 每来源 p95 时延落在 §8.1 deadline 候选内；7 天滚动窗口。
- Shadow 运行环境与数据同样受 G3 约束（本地合成）；shadow 结果与离线结果分册报告，不得合并口径。

## 9. FAIL CLOSED 判定规则（程序性规则，非数值候选）

以下任一成立 ⇒ 相应门禁判定为 **FAIL**（不是"暂缓"或"带保留通过"）；依据：实施计划 §6.4"证据不足不能算通过"、设计规格 §19.4：

1. gold set 无版本 + SHA-256 manifest（数据未冻结）→ 全部 DS/Q/E/P 门禁 FAIL；
2. 任一样本量下限（DS-3/DS-5/E-2/P-3/S-2）未达到 → 该指标 FAIL（证据不足）；
3. 任一 CI 条件不满足（Q-4 CI 含 0；E-1 Wilson 上界超限；P-1/P-2 CI 下界不足）→ 该指标 FAIL；
4. 标注一致性 κ < 0.70 或仲裁未完成 → 依赖该标注的全部指标 FAIL；
5. BM25 baseline 缺失、配置不可复现或其 manifest 缺失 → 全部 Q 门禁 FAIL；
6. Z1/Z2/Z3 任一自动化断言失败 → 本次评测整体无效，且按实施计划 Task 门禁独立阻塞（与数值门禁并行，不互抵）；
7. 评测环境非本地合成（G3 未满足）或运行 manifest 不完整（数据集版本/哈希、种子、配置哈希、环境规格、CI 算法版本任一缺失）→ 运行无效 → FAIL；
8. 评测报告声称 shadow 推断收益（违反 §7 边界）→ 报告无效。
9. **FAIL 之后的路径：** 基础设施故障类失败允许登记原因后重跑（≤ 2 次，原因入报告）；指标不达标类失败**不允许**通过改种子、改样本、改配置重跑"刷过"（反 cherry-picking）；数据集缺陷类失败走 §10.2 变更控制修订数据集（MAJOR 版本），不得静默修补。

## 12. 可执行评测与失败判定流程（不写代码）

每次评测运行（离线冻结运行、成对运行、合成 shadow 窗口汇总）按以下顺序执行；每步的产物与失败出口对齐 §9：

1. **前置校验：** 确认环境 = 本地合成（G3）；确认 gold set 版本 + SHA-256 manifest、标注指南版本、种子清单、评测器构建/配置哈希齐备；任一缺失 → FAIL（§9.1/§9.7）。
2. **冻结运行配置：** 记录检索参数、融合权重、topK、一致性偏好、模型/温度/种子（成对运行）、引擎与客户端版本（随 G2 落地后引用）；生成运行 manifest。
3. **运行 BM25 baseline**（§4.4 定义），记录其逐 query 指标与配置哈希；baseline 不可复现 → FAIL。
4. **运行被测系统**（混合检索；成对运行则 off/on 两臂 + 消融臂），相同数据集版本与种子；输出逐 query/逐任务原始结果。
5. **计算指标：** 按 §4/§5/§6/§7/§8 定义与单位计算，附分层与整体宏平均、逐窗口分列；CI 按 Q-4/P-4/E-1 算法计算，算法版本入 manifest。
6. **执行机制断言：** Z1/Z2/Z3 套件、token 硬上限、deadline 取消行为；任一失败 → 运行整体无效并独立阻塞。
7. **应用门禁：** 冻结 manifest 存在 → 逐条比对并输出结论；不存在 → 输出"UNAPPROVED — informational only"（§11.3）。
8. **失败判定（若 FAIL）：** 分类根因——基础设施故障（可登记重跑 ≤ 2 次）/ 数据集缺陷（走 §10.2，MAJOR 版本）/ 实现缺陷（修复后重新运行全流程）/ 真实不达标（结论成立，进入 owner 复审或发布否决）；禁止选择性重跑（§9.9）。
9. **产出报告：** 运行 manifest + 指标表（分层/整体/逐窗口）+ CI + 机制断言结果 + 门禁逐条结论（或 UNAPPROVED 标注）+ 失败根因与重跑记录；报告与 manifest 一起归档，构成 Task 11/14 验收证据（实施计划 §17.6/§20.4）。
10. **复审触发：** 命中 §10.2 任一触发条件时，报告转入四方变更控制，流程回到本清单第 1 步（新数据集/新冻结 manifest 下重测）。
